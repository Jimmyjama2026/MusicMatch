# Second review and next-round proposals

Reviewed October 31, 2026 by the primary agent and one independent devil's-advocate agent. No additional agents or downloads were used for this review. The independent review covered enrichment, acquisition, text-index persistence, desktop integration and regression coverage; the primary review focused on ranking/exclusions, stored provenance and desktop behavior. The agents exchanged reproductions and reviewed the corrections together.

## Corrections made before user testing

1. **Stale current suggestions after Fresh exhaustion.** A metadata-only favorite with cached provider relationships could exhaust all eligible results and raise a misleading missing-data error. That bypassed the desktop's normal empty-result handling. It now returns an empty result when relationships exist but exclusions exhaust them; genuinely absent relationship data still gets the explicit missing-data message. A real Tk/HybridRecommender/FeedbackStore regression verifies that the current batch clears while favorites and history survive.
2. **Excluded song repeated under another source ID.** Incomplete artist credits correctly prevented recording mapping, but also left a metadata alias outside Fresh/No exclusions. A bounded identity index now applies the existing title/artist deduplication policy to exclusions across sources. It does not establish recording equivalence for audio mapping or copy audio measurements. The index is populated during the existing catalog/title-prefilter pass; there is no new normalization scan of all 200,000 audio rows per query. Regression checks cover both exclusion directions, direct No feedback and original-audio fallback.
3. **Duplicate consumed a discovery slot.** Deduplicating after selecting the requested count could return fewer results even when another eligible unique discovery existed. Each candidate channel is now deduplicated before selection, and discoveries already represented in the audio channel are skipped. The separate, at-most-one discovery slot policy is unchanged.
4. **Incorrect audio provenance on metadata discoveries.** Metadata-only discoveries no longer receive an `audio_model_version`. Only results actually scored by the audio engine carry that provenance.

The full suite passes **52 tests in 12.03 seconds**, including the new desktop regression and four new hybrid tests. The independent agent reread the corrections and reported no remaining blocker for testing. Production widgets, layout and scrolling were unchanged; personal database contents were not edited by the tests. Optional enrichment still loads offline and all application search/recommendation work uses the existing background worker.

A new smoke measurement against the saved 4,115-entry catalog loaded all 725 usable relationships without warnings and returned five suggestions. Six alternating warm requests averaged **233 ms original / 237 ms enriched**; maxima were **274 / 294 ms**. Startup took 4.72 seconds. These timings vary with machine load and are not a guarantee; compare paired runs rather than the absolute numbers from the earlier session. See [raw review measurements](enrichment_review_performance.json).

## Agreed next-round priorities — proposals, not implemented

1. **Make coverage understandable when choosing favorites.** Add a compact indication of available audio/listening evidence before Add, plus a studio/live/remix filter where source metadata supports it. Missing evidence should be visible before someone builds a favorite list that cannot supply recommendations. Avoid inferring recording type when the source is ambiguous.
2. **Measure quality before tuning weights.** Use fixed favorites and a fixed source snapshot to compare original and enriched suggestions with source labels hidden during judging. Keep evaluation labels out of ranker input until the comparison is complete. Record approval rate, judged count, source coverage and the fraction of rankings actually changed. This distinguishes an active discovery-slot test from a mostly dormant audio reranker.
3. **Respect feedback intent.** “Already know it” should suppress repeat suggestions without teaching the model that the artist or sound is disliked. Separate familiarity from taste signals, preserving previous history and explaining the distinction simply.
4. **Improve verified recording joins before expanding volume.** Audit frequently used favorites/candidates using source identifiers, duration and full artist credits. Better identity coverage can activate audio-plus-listening ranking for existing recordings with little extra storage. Uncertain joins must remain uncertain; metadata alone cannot create audio features.
5. **Support deliberate source/index updates.** The current API cache has no expiry or refresh switch: rerunning acquisition reuses earlier responses, so it is suitable for resuming this snapshot but does not guarantee newly released material appears. Add explicit bounded refresh/revalidation while retaining offline resume behavior. Text index directories currently depend on the corpus hash; a future model-version change needs a new directory key or explicit rebuild command. Neither limitation blocks testing the current frozen data.

The text experiment should remain separate until permitted text and verified song overlap exist. Evaluate same-language lexical matches before considering semantic representations. Richer sound analysis remains deferred as requested.

No improvement in recommendation quality is claimed from passing tests or returning a provider discovery. Next-round implementation should follow review of these proposals.
