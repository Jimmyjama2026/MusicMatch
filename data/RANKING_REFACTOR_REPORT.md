# Recommendation cleanup and controlled artist adjustment

Implemented October 31, 2026. No subscriptions, source downloads, dependency installs, or writes to the personal feedback database were performed by this ranking task.

## Changes and their separate purposes

The default same-artist bonus is **.18**, previously .20. This is a 10% reduction in a score subtraction, not an 18% probability or a learned preference. Other existing weights remain unchanged: additional Yes-anchor penalty .08, maximum local dislike penalty .04, group diversity penalty .06, rich listening support bonus .02 and rich artist-vote bound .005. The unchanged four-feature backend remains the fallback. Configuration is immutable and every rich result records policy version, all parameter values and a SHA-256 fingerprint.

Canonical title and full artist-credit identities now normalize Unicode, apostrophes, whitespace, collaborator order and every semicolon spacing variant. Shared identities govern rich favorite/No/Fresh/focused exclusions, selection deduplication and learning-record partitions. Stable provider artist IDs take priority over names when available; Spotify and MusicBrainz namespaces remain distinct. These text identities are exclusion aliases, not permission to copy measurements between recordings. Learning split version is bumped to v2 because canonical identities can alter partitions.

One shared selector deduplicates before artist/group caps. A separate selection trace reports the group-usage diversity adjustment, artist counts and cap relaxation; these are not double-added to the underlying ranking score. Candidate retrieval preserves raw leaders plus bounded artist-limited group representatives, so a first fifty crowded with one artist cannot erase every alternative before final selection.

The rich hybrid path now unions its acoustic retrieval pool with at most 1,000 **conservatively joined audio-catalog recordings** from cached listening relationships. Each graph candidate receives the same anchor-based rich distance, artist and feedback terms as other candidates, before the existing bounded listening adjustment. Unknown-audio metadata is not imputed or forced into a rich-audio batch, even when that channel is exhausted. Metadata-only favorites retain their explicitly labelled provider route. Available/requested/eligible graph counts, capping and union size are recorded. Graph support describes listening association, not similar sound.

Public audio interfaces (`has_song`, `has_audio_features`, `songs_with_titles`, `score_candidates`) replace hybrid access to private audio fields. Index fitting remains offline; querying performs no network requests or training. Canonical catalog credits and identity keys are cached on the loading worker to avoid per-request catalog normalization.

## What the measurements establish

Ignored `data/evaluation/` contains frozen inputs, source hashes, full results and timings. The pre-change capture inadvertently selected **Personal**, while the active profile was **Test**. This limitation is preserved explicitly:

- Personal has one favorite and one Yes. Its pre-cleanup .20 result and a pre-cleanup .18-only ablation were captured before refactoring. Under refactored .20, the same ten IDs and scores were reproduced exactly (maximum score delta 0.0). This establishes parity for that frozen case only.
- Active Test has six favorites, seven Yes judgments and **zero taste-No judgments**. Its .20 and .18 controls both use identical post-cleanup code. Their top-five overlap was five out of five. They isolate the parameter change under current code; they must not be presented as an active-profile before/after cleanup experiment.
- Final active-Test rich requests had eleven eligible graph/audio joins, no graph capping, and 1,011 union candidates. An intermediate implementation took 1.2–1.4 seconds because a rare group forced a global Python retrieval loop and subset queries scanned global queues. The performance gate replaced that work with vectorized identity codes, bounded groupwise retrieval, an explicit-subset fast path and cached selector credits/config provenance. Six subsequent warm ten-result requests took **199, 259, 228, 201, 196 and 211 ms**. The final hybrid path also retains graph rows from the existing full-catalog distance pass instead of recomputing anchors and masks in a second scoring call; six latest concurrent-machine measurements were **238, 248, 245, 240, 245 and 238 ms**. Both checks returned identical ten result IDs and maximum score difference **0.0** versus frozen pre-optimization output. Machine-load variation prevents treating these unpaired timing sets as a comparison between the last two implementations. The historical approximately 154 ms six-favorite measurement omits the current seven-Yes context and is not a valid matched baseline. These are worker computation timings, not proof of GUI responsiveness or ranking quality.
- The historical James Arthur “Quite Miss Home” versus Olivia Rodrigo “drivers license” development pair reproduces distance **0.03542676195502281**, with artist adjustment zero. This preserves the numerical cross-artist example, not an explanation of why the user liked it, a held-out test, or a special James Arthur rule.

No trained preference model is enabled: seven positives without taste negatives do not support the planned comparative learner. Existing Yes examples still act as bounded positive anchors. More labels and independently judged, identity/time-separated evaluation are prerequisites for claiming quality improvement. Lyrics remain outside personal ranking.

## Verification

The ranking, identity, hybrid and learning-record suites pass **47 tests**. New checks cover explicit subset/full-metric equality, candidate validation/bounds, canonical Fresh/focused exclusions, a close cross-artist candidate beating a sufficiently distant same-artist candidate, graph candidates outside the first fifty, artist diversity beyond fifty same-artist candidates, preserved raw graph distances, configuration provenance and no metadata substitution after rich exhaustion. The independent reviewer identified the intermediate diversity/exclusion/provenance issues; each was repaired with regression coverage.

Actual experiments and limitations are recorded separately from parameter changes: `baseline_artist020.json`, `ablation_artist018_only.json`, `active_parameter_control.json`, and `ranking_cleanup_report.json` under the ignored evaluation directory. Passing tests or unchanged top-five lists is not evidence that recommendation quality improved.
